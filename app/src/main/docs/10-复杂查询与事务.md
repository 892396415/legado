## 一、复杂查询基础

### 1.1 SQL 查询在 Room 中的写法

```kotlin
@Dao
interface BookDao {
    
    // 基础查询
    @Query("SELECT * FROM books")
    fun getAll(): List<Book>
    
    // 条件查询
    @Query("SELECT * FROM books WHERE bookUrl = :url")
    fun getByUrl(url: String): Book?
    
    // 复杂查询 - 多条件 + 排序 + 分页
    @Query("""
        SELECT * FROM books 
        WHERE type & :type > 0 
        AND `group` & :group > 0
        ORDER BY durChapterTime DESC 
        LIMIT :limit OFFSET :offset
    """)
    fun getComplex(type: Int, group: Long, limit: Int, offset: Int): List<Book>
}
```

### 1.2 Kotlin 多行字符串

Room 支持使用 Kotlin 的三引号 `"""` 来编写格式化的 SQL：

```kotlin
@Query("""
    SELECT * FROM books 
    WHERE name LIKE '%' || :key || '%'
    ORDER BY durChapterTime DESC
""")
```

**优点**：
- 代码可读性更好
- 支持 SQL 高亮和格式化
- 避免字符串拼接

## 二、多表联合查询

### 2.1 JOIN 类型对比

| JOIN 类型 | 说明 | 使用场景 |
|-----------|------|----------|
| `INNER JOIN` | 返回两表匹配的行 | 必须关联的数据 |
| `LEFT JOIN` | 返回左表所有行，右表匹配的行 | 可能为空的关联 |
| `RIGHT JOIN` | 返回右表所有行，左表匹配的行 | SQLite 不支持 |
| `FULL JOIN` | 返回两表所有行 | SQLite 不支持 |
| `CROSS JOIN` | 笛卡尔积 | 生成组合数据 |

### 2.2 INNER JOIN - 内连接

**场景**：获取搜索结果及其对应的书源信息

```kotlin
@Dao
interface SearchBookDao {
    
    @Query(
        """
        SELECT t1.name, t1.author, t1.origin, t1.originName, t1.coverUrl, 
               t1.bookUrl, t1.type, t1.time, t1.intro, t1.kind, 
               t1.latestChapterTitle, t1.tocUrl, t1.variable, t1.wordCount,
               t2.customOrder as originOrder
        FROM searchBooks AS t1 
        INNER JOIN book_sources AS t2 
        ON t1.origin = t2.bookSourceUrl 
        WHERE t1.name = :name 
        AND t1.author LIKE '%' || :author || '%'
        AND t2.enabled = 1
        ORDER BY t2.customOrder
        """
    )
    fun getEnableHasCover(name: String, author: String): List<SearchBook>
}
```

**解析**：
- `t1`, `t2`：表别名，简化代码
- `ON t1.origin = t2.bookSourceUrl`：连接条件
- `t2.enabled = 1`：只查询启用的书源
- 只返回有关联书源的搜索结果

### 2.3 LEFT JOIN - 左连接

**场景**：获取 RSS 文章及其阅读状态（可能没有阅读记录）

```kotlin
@Dao
interface RssArticleDao {
    
    @Query(
        """
        SELECT t1.link, t1.sort, t1.origin, t1.`order`, t1.title, 
               t1.content, t1.description, t1.image, t1.`group`, 
               t1.pubDate, t1.variable, 
               IFNULL(t2.read, 0) AS read
        FROM rssArticles AS t1 
        LEFT JOIN rssReadRecords AS t2
        ON t1.link = t2.record  
        WHERE t1.origin = :origin 
        AND t1.sort = :sort
        ORDER BY t1.`order` DESC
        """
    )
    fun flowByOriginSort(origin: String, sort: String): Flow<List<RssArticle>>
}
```

**解析**：
- `LEFT JOIN`：返回所有文章，即使没有被阅读过
- `IFNULL(t2.read, 0)`：如果没有阅读记录，默认返回 0（未读）
- 适用于主表必须显示，关联表可能为空的场景

### 2.4 多表连接

**场景**：获取搜索结果、书源信息并过滤分组

```kotlin
@Dao
interface SearchBookDao {
    
    @Query(
        """
        SELECT t1.name, t1.author, t1.origin, t1.originName, 
               t1.coverUrl, t1.bookUrl, t1.type, t1.time,

        AND t2.enabled = 1 
        AND t2.bookSourceGroup LIKE '%' || :sourceGroup || '%'
        AND (t1.originName LIKE '%' || :key || '%' 
             OR t1.latestChapterTitle LIKE '%' || :key || '%')
        ORDER BY t2.customOrder
        """
    )
    fun changeSourceSearch(
        name: String,
        author: String,
        key: String,
        sourceGroup: String
    ): List<SearchBook>
}
```

## 三、子查询

### 3.1 WHERE 子查询

**场景**：查询有书籍的分组

```kotlin
@Dao
interface BookGroupDao {
    
    @Query(
        """
        SELECT * FROM book_groups 
        WHERE show > 0 
        AND (
            groupId >= 0 
            AND EXISTS (
                SELECT 1 FROM books 
                WHERE `group` & book_groups.groupId > 0
            )
        )
        ORDER BY `order`
        """
    )
    fun flowHasBooks(): Flow<List<BookGroup>>
}
```

**解析**：
- `EXISTS (SELECT 1 FROM ...)`：检查是否存在关联数据
- `SELECT 1`：只检查存在性，不返回实际数据，效率更高
- 用于过滤有实际内容的分组

### 3.2 FROM 子查询

**场景**：使用 CTE (Common Table Expression) 计算分组总和

```kotlin
@Dao
interface BookGroupDao {
    
    @get:Query(
        """
        WITH const AS (
            SELECT SUM(groupId) sumGroupId 
            FROM book_groups 
            WHERE groupId > 0
        )
        SELECT book_groups.* 
        FROM book_groups 
        JOIN const 
        WHERE show > 0 
        AND (
            (groupId >= 0 AND EXISTS (
                SELECT 1 FROM books WHERE `group` & book_groups.groupId > 0
            ))
            OR groupId = -1
            OR (groupId = -2 AND EXISTS (
                SELECT 1 FROM books WHERE type & ${BookType.local} > 0
            ))
            OR (groupId = -3 AND EXISTS (
                SELECT 1 FROM books WHERE type & ${BookType.audio} > 0
            ))
            OR (groupId = -11 AND EXISTS (
                SELECT 1 FROM books WHERE type & ${BookType.updateError} > 0
            ))
        )
        ORDER BY `order`
        """
    )
    val show: LiveData<List<BookGroup>>
}
```

**解析**：
- `WITH const AS (...)`：定义临时结果集
- `const.sumGroupId`：所有分组的 ID 总和
- 用于位运算判断书籍是否属于某个分组

### 3.3 IN 子查询

**场景**：查找有效书源的搜索结果

## 五、位运算查询

### 5.1 位运算原理

使用位运算存储多选状态，一个字段存储多个标记：

```kotlin
object BookType {
    const val text = 0        // 0000 文本
    const val audio = 1       // 0001 音频 (2^0)
    const val image = 2       // 0010 图片 (2^1)
    const val local = 4       // 0100 本地 (2^2)
    const val webFile = 8     // 1000 文件 (2^3)
}

// type = 5 (0101) 表示：local + text
```

### 5.2 位运算查询语法

| 运算 | SQL 语法 | 含义 |
|------|---------|------|
| 检查标记 | `type & ${BookType.audio} > 0` | 是否包含音频标记 |
| 检查多个 | `type & (${BookType.audio} \| ${BookType.local}) > 0` | 是否包含音频或本地 |
| 排除标记 | `type & ${BookType.local} = 0` | 不包含本地标记 |
| 精确匹配 | `type = ${BookType.text}` | 只匹配文本类型 |

### 5.3 实战案例

```kotlin
@Dao
interface BookDao {
    
    // 查询所有音频书
    @Query("SELECT * FROM books WHERE type & ${BookType.audio} > 0")
    fun flowAudio(): Flow<List<Book>>
    
    // 查询所有本地书
    @Query("SELECT * FROM books WHERE type & ${BookType.local} > 0")
    fun flowLocal(): Flow<List<Book>>
    
    // 查询网络文本书（非本地 + 非音频）
    @Query(
        """
        SELECT * FROM books 
        WHERE type & ${BookType.audio} = 0 
        AND type & ${BookType.local} = 0
        """
    )
    fun flowNetText(): Flow<List<Book>>
    
    // 查询更新失败的书
    @Query("SELECT * FROM books WHERE type & ${BookType.updateError} > 0")
    fun flowUpdateError(): Flow<List<Book>>
    
    // 查询同时满足多个条件的
    @Query(
        """
        SELECT * FROM books 
        WHERE type & ${BookType.local} > 0 
        AND type & ${BookType.audio} > 0
        """
    )
    fun flowLocalAudio(): Flow<List<Book>>
}
```

## 六、视图查询

### 6.1 什么是视图

视图是虚拟表，基于 SQL 查询结果的逻辑表：

```kotlin
// 定义视图 Entity
@Entity(
    tableName = "book_sources_part",  // 实际是一个视图
)
data class BookSourcePart(
    @PrimaryKey
    val bookSourceUrl: String,
    val bookSourceName: String,
    val bookSourceGroup: String?,
    val customOrder: Int,
    val enabled: Boolean
    // ... 部分字段
)
```

### 6.2 查询视图

```kotlin
@Dao
interface BookSourceDao {
    
    // 直接查询视图
    @Query("SELECT * FROM book_sources_part WHERE enabled = 1")
    fun flowEnabled(): Flow<List<BookSourcePart>>
    
    // 视图与表联合查询
    @Query(
        """
        SELECT bp.*
        FROM book_sources b 
        JOIN book_sources_part bp ON b.bookSourceUrl = bp.bookSourceUrl 
        WHERE b.enabled = 1
        ORDER BY b.customOrder
        """
    )
    fun flowEnabledPart(): Flow<List<BookSourcePart>>
}
```

### 6.3 视图的优势

1. **简化查询**：将复杂查询封装为视图
2. **数据安全**：只暴露需要的字段
3. **性能优化**：预计算的查询结果
4. **逻辑分离**：业务逻辑与数据存储分离

## 七、事务基础

### 7.1 什么是事务

**事务**是一组数据库操作，要么全部成功，要么全部失败（原子性）。

```
事务开始前：
┌─────────┬──────────┐
│  表 A   │   表 B   │
├─────────┼──────────┤
│ 数据 A1 │  数据 B1 │
│ 数据 A2 │  数据 B2 │
└─────────┴──────────┘

事务中：
1. 更新表 A ✓
2. 更新表 B ✓
3. 提交事务 ✓

结果：都成功，数据生效

=============================

事务中：
1. 更新表 A ✓
2. 更新表 B ✗ (失败)
3. 回滚事务 ✓

结果：都失败，数据回到初始状态
```

### 7.2 事务的 ACID 特性

| 特性 | 说明 | Room 保证 |
|------|------|-----------|
| **A**tomicity (原子性) | 操作要么全成功，要么全失败 | `@Transaction` |
| **C**onsistency (一致性) | 数据完整性约束始终满足 | Room 自动处理 |
| **I**solation (隔离性) | 并发事务互不影响 | SQLite 默认 SERIALIZABLE |
| **D**urability (持久性) | 提交后数据永久保存 | SQLite 保证 |

### 7.3 Room 事务注解

```kotlin
@Dao
interface BookSourceDao {
    
    // 标记事务方法
    @Transaction
    fun deleteBatch(sources: List<BookSourcePart>) {
        for (source in sources) {
            delete(source.bookSourceUrl)
        }
    }
}
```

### 7.4 自动事务场景

Room 自动在以下场景启用事务：

1. **@Insert、@Update、@Delete** 批量操作
2. **@Query** 单个查询
3. **嵌套事务**：支持事务嵌套

## 八、事务实战

### 8.1 批量删除

```kotlin
@Dao
interface BookSourceDao {
    
    // 单条删除
    @Query("DELETE FROM book_sources WHERE bookSourceUrl = :url")
    fun delete(url: String)
    
    // 批量删除（需要事务）
    @Transaction
    fun deleteBatch(sources: List<BookSourcePart>) {
```

### 8.4 批量更新分组

```kotlin
@Dao
interface BookSourceDao {
```

### 8.5 复合事务操作

**场景**：删除书源时同时清理相关数据

```kotlin
@Dao
abstract class BookSourceDao {
    
    @Query("DELETE FROM book_sources WHERE bookSourceUrl = :url")
    abstract fun deleteSource(url: String)
    
    @Query("DELETE FROM searchBooks WHERE origin = :url")
    abstract fun deleteSearchBooks(url: String)
    
    @Query("DELETE FROM cookies WHERE url = :url")
    abstract fun deleteCookies(url: String)
    
    // 复合删除操作
    @Transaction
    open fun deleteSourceCompletely(url: String) {
        deleteCookies(url)
        deleteSearchBooks(url)
        deleteSource(url)
        // 三个操作在一个事务中
        // 任意一个失败都会回滚
    }
}
```

## 十、最佳实践

### 10.1 查询最佳实践

```kotlin
@Dao
interface BookDao {
    
    // ✅ 使用具名参数
    @Query("SELECT * FROM books WHERE bookUrl = :url AND name = :name")
    fun find(url: String, name: String): Book?
    
    // ✅ 复杂查询使用多行字符串
    @Query(
        """
        SELECT * FROM books 
        WHERE type & :type > 0 
        AND `group` & :group > 0
        ORDER BY durChapterTime DESC
        """
    )
    fun search(type: Int, group: Long): List<Book>
    
    // ✅ 使用 IFNULL 处理 NULL 值
    @Query(
        """
        SELECT t1.*, IFNULL(t2.read, 0) as read
        FROM articles t1 
        LEFT JOIN records t2 ON t1.id = t2.id
        """
    )
    fun getWithReadStatus(): List<Article>
}
```

### 10.2 事务最佳实践

```kotlin
@Dao
interface BookDao {
    
    // ✅ 批量操作使用事务
    @Transaction
    fun deleteBatch(books: List<Book>) {
        books.forEach { delete(it) }
    }
    
    // ✅ 相关操作使用事务
    @Transaction
    fun replaceBookChapters(
        book: Book, 
        oldChapters: List<BookChapter>,
        newChapters: List<BookChapter>
    ) {
        deleteChapters(oldChapters)
        insertChapters(newChapters)
        update(book)
    }
    
    // ✅ 检查事务结果
    @Transaction
    fun safeUpdate(book: Book): Boolean {
        return try {
            update(book)
            true
        } catch (e: Exception) {
            false  // 事务自动回滚
        }
    }
}
```

### 10.4 常见错误

```kotlin
@Dao
interface BookDao {
    
    // ❌ 错误：忘记添加 % 在 LIKE 查询中
    @Query("SELECT * FROM books WHERE name LIKE :key")
    fun searchWrong(key: String): List<Book>
    
    // ✅ 正确
    @Query("SELECT * FROM books WHERE name LIKE '%' || :key || '%'")
    fun searchCorrect(key: String): List<Book>
    
    // ❌ 错误：在事务中捕获异常
    @Transaction
    fun wrongTransaction() {
        try {
            operation1()
            operation2()  // 失败
        } catch (e: Exception) {
            // 错误：不要在这里捕获异常
        }
    }
    
    // ✅ 正确：让异常抛出，自动回滚
    @Transaction
    fun correctTransaction() {
        operation1()
        operation2()  // 失败时自动回滚
    }
}
```
